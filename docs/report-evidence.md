# หลักฐานสำหรับรายงาน Pokatop

ไฟล์นี้รวบรวมภาพ log และคำอธิบายตามหัวข้อที่เอกสารโจทย์กำหนด คัดลอกข้อความไปใช้ในรายงานได้เลย
ภาพทั้งหมดอยู่ใน `docs/evidence/` ไฟล์ที่ขึ้นต้นด้วย `t12-` ถ่ายหลังแอปเสร็จแล้ว บน emulator Pixel_8 (Android API 37)

---

## 1. ไอคอน ภาพหน้าหลัก และคำบรรยายแอป

- ไอคอน: `t12-icon.png` — ตัว P สีกรมท่าบนพื้นมิ้นต์ ส่วนหัวของ P เป็นวงนับเวลาที่ยังไม่ครบรอบ สื่อชื่อแอปและการจับเวลา (ออกแบบเอง วาดเป็น vector)
- หน้าหลัก: `t12-flow-01-waiting.png`

**คำบรรยาย**
Pokatop เป็นแอปจับเวลาอ่านหนังสือแบบ Pomodoro ที่ใช้ท่าทางของมือถือเป็นตัวควบคุม ผู้ใช้เพียงคว่ำมือถือลงบนโต๊ะ แอปจะเริ่มนับเวลาอ่านทันที และหรี่จอเป็นสีดำ
ถ้าหยิบมือถือขึ้นมาเกิน 10 วินาที หรือสลับไปใช้แอปอื่น แอปจะหยุดเวลาและนับว่า "เสียสมาธิ" 1 ครั้ง เมื่อครบรอบจะมีเสียงและการสั่นเตือนให้พัก พักยาวทุก 4 รอบ
ผู้ใช้เลือกช่วงเวลาได้ 6 แบบ (รวมกำหนดเอง) ปิดการตรวจจับเพื่อใช้เป็นตัวจับเวลาธรรมดาได้ และดูสถิติ 7 วันกับประวัติการอ่านย้อนหลังได้ รองรับภาษาไทย/อังกฤษ และธีมสว่าง/มืด

## 4. ฟังก์ชันการทำงานและความสามารถเชิงเทคนิค

### 4.1 ตรวจท่าคว่ำ/หยิบด้วย accelerometer (`sensing/FilteredFlipDetector.kt`)
- อ่าน `Sensor.TYPE_ACCELEROMETER` ที่ `SENSOR_DELAY_GAME` (~50 ครั้ง/วินาที) ลงทะเบียนใน `onResume` และยกเลิกใน `onPause`
- แยกแรงโน้มถ่วงด้วย low-pass filter: `g = 0.8·g + 0.2·z`
- ใช้สองเกณฑ์ (hysteresis):
  - **คว่ำ** เมื่อ g ≤ −8.0 ต่อเนื่อง 800 ms (มือถือคว่ำเอียงได้ถึงราว 35°)
  - **หยิบ** เมื่อ g ≥ −6.0 ต่อเนื่อง 300 ms
  - ค่าระหว่างสองเกณฑ์ไม่เปลี่ยนสถานะ จึงไม่กระพริบ
- เป็นคลาส Kotlin ล้วน ไม่ใช้ Android API จึงทดสอบด้วย JUnit จากชุดค่าที่สร้างขึ้นได้ (`FilteredFlipDetectorTest`)

### 4.2 ตรรกะรอบอ่าน (`timer/FocusSession.kt`) — state machine
```
WAITING ──คว่ำ──▶ FOCUSING ──หยิบ──▶ GRACE ──คว่ำกลับภายใน 10 วิ──▶ FOCUSING
                                       └──เกิน 10 วิ──▶ PAUSED (+1 เสียสมาธิ, ตัดเวลาย้อนไปตอนหยิบ)
FOCUSING/GRACE ──สลับแอป / ปุ่ม power──▶ PAUSED (+1)      PAUSED ──คว่ำ──▶ FOCUSING
FOCUSING ──ครบเวลา──▶ BREAK (ยาวทุก N รอบ) ──ครบเวลาพัก──▶ WAITING (ต้องหยิบแล้วคว่ำใหม่)
โหมดธรรมดา: WAITING ─เริ่ม▶ FOCUSING ─หยุด/สลับแอป▶ PAUSED ─ทำต่อ▶ FOCUSING (ไม่นับเสียสมาธิ)
```
- เวลาไม่ได้นับจาก tick ของ Handler แต่จาก `SystemClock.elapsedRealtime()` เป็นช่วง ๆ (เวลาสะสม + จุดเริ่มช่วง) จึงไม่คลาดแม้เครื่องทำงานหนัก
- Handler ใช้รีเฟรชหน้าจอทุก 250 ms เท่านั้น
- ทดสอบด้วย JUnit 20 กรณีใน `FocusSessionTest`

### 4.3 เก็บสถานะ
- **หมุนจอ:** `onSaveInstanceState` เก็บสถานะทั้งหมดเป็นข้อความ (`SessionCodec`)
- **ระบบปิดแอปเบื้องหลัง:** เขียนลง SharedPreferences ใน `onPause` เปิดใหม่แล้วกลับมาที่สถานะหยุดชั่วคราวพร้อมเวลาเดิม
- ข้อมูลเสียหายจะได้ตัวจับเวลาใหม่ แอปไม่ crash

### 4.4 ฐานข้อมูล
- SQLiteOpenHelper ตาราง `sessions`: เวลาเริ่ม-จบ, ช่วงที่ใช้, โหมด, เวลาอ่าน, รอบ, เสียสมาธิ
- สถิติรายวันคำนวณใน `timer/DailyStats.kt` (ทดสอบด้วย JUnit)

### 4.5 วาดเอง
- `TimerRingView` (วงนับเวลา) และ `WeekBarChartView` (กราฟแท่ง) วาดด้วย Canvas ไม่ใช้ไลบรารีภายนอก

### 4.6 การเชื่อมโยงเนื้อหา
- **วิชา CS364 (rubric 1.3):**
  - MA05 event/sensor
  - MA06 alternative resources (ภาษา/ธีม/`layout-land`/`values-h720dp`)
  - MA07 Activity lifecycle + configuration change
  - MA08 input controls (Switch, RadioButton, Chip, ปุ่ม +/−)
  - MA09 SharedPreferences + instance state
  - MA10 SQLite + RecyclerView
  - MA12 sensors (accelerometer)
  - MA02 core app quality (ยืนยันก่อนลบ, ข้อความชัดเจน, touch target ≥ 48dp)
- **วิชาอื่น (rubric 1.4):**
  - ฟิสิกส์: เวกเตอร์แรงโน้มถ่วง และมุมเอียง cos θ = −z/9.8
  - signal processing: low-pass filter
  - ทฤษฎีออโตมาตา: state machine
  - จิตวิทยาการเรียนรู้: เทคนิค Pomodoro

## 5. ความท้าทายทางเทคนิค (ปัญหา → สาเหตุ → วิธีแก้ → หลักฐาน)

### 5.1 คว่ำมือถือแล้วจอดับเอง จนนับว่าเสียสมาธิทั้งที่ยังไม่ได้หยิบ
- **ปัญหา:** คว่ำมือถือเพื่อเริ่มอ่าน แอปกลับนับ "เสียสมาธิ" ทันที (ฟังก์ชันหลัก หน้าจับเวลา)
- **สาเหตุ:**
  - Android มี FaceDownDetector ใน PowerManagerService (log `onFlip(): Face down`) ซึ่งปิดจอเมื่อเครื่องคว่ำ
  - จอดับทำให้ Activity เข้า `onPause` ซึ่งแอปถือว่าเป็นการออกจากแอป
  - เดิมแอปขอให้จอเปิดค้าง (`FLAG_KEEP_SCREEN_ON`) เฉพาะตอนที่มีรอบกำลังนับ จึงไม่ครอบคลุมช่วงรอคว่ำครั้งแรก
- **วิธีแก้:**
  - เปิด `FLAG_KEEP_SCREEN_ON` ตลอดเวลาที่โหมดตรวจจับเปิดและหน้าจับเวลาอยู่หน้าจอ (`MainActivity.render`)
  - ปุ่ม power และการสลับแอปยังนับเป็นการออกจากแอปตามเดิม
- **หลักฐาน:**
  - ก่อนแก้: `t12-ch1-screenoff-before.txt`
    - log จริงที่บันทึกตอนพัฒนา (00:50) มี `Display-off`, Activity ถูก pause แบบ `sleep` แล้วตามด้วย `distraction reason=leave`
    - **หมายเหตุ:** ทดลองซ้ำภายหลังแล้วเกิดไม่ทุกครั้ง เพราะต้องเป็นจังหวะที่ระบบปิดจอก่อนแอปรับรู้ว่าคว่ำ (เช่น คว่ำทันทีหลังเปิดแอป) จึงใช้หัวข้อนี้เป็นเรื่องเสริม เรื่องหลักแนะนำให้ใช้ 5.2 หรือ 5.3
  - หลังแก้: `t12-ch1-screenoff-after.txt` (FOCUSING ต่อเนื่อง ไม่มี pause)
  - เทสต์: `MainActivityScreenOnTest` ตรวจว่าเปิด keep-screen-on ตั้งแต่ตอนรอคว่ำ (ล้มก่อนแก้ ผ่านหลังแก้)

### 5.2 ค่า accelerometer สั่น / วางมือถือเอียง จนแอปคิดว่าหยิบขึ้นมา
- **ปัญหา:**
  - รุ่นแรกใช้เกณฑ์เดียว z ≤ −9.0 ถึงจะเรียกว่าคว่ำ (`NaiveFlipDetector`)
  - เมื่อวางมือถือคว่ำบนหนังสือที่เอียง 25° (z ≈ −8.88) หรือโต๊ะสั่น ค่ากระโดดข้ามเกณฑ์ไปมา
  - ผลคือแอปเข้าใจว่าหยิบขึ้นมา และนับเสียสมาธิผิด
- **สาเหตุ:** ค่าดิบของ sensor มีสัญญาณรบกวน และแรงโน้มถ่วงบนแกน z ลดลงตามมุมเอียง (−9.8·cos θ)
- **วิธีแก้:**
  - `FilteredFlipDetector`: low-pass filter
  - สองเกณฑ์ −8.0/−6.0 (hysteresis)
  - ต้องคงค่าต่อเนื่อง 800/300 ms (debounce)
  - เปลี่ยนตัวที่ใช้ใน `Detectors.create()`
- **หลักฐาน:**
  - ข้อมูลสั่น 5 วินาทีชุดเดียวกัน (z = −9.6 ± 1.2 ที่ 50 Hz): แบบเดิมเปลี่ยนสถานะ **104 ครั้ง** แบบใหม่ **0 ครั้ง** (`FilteredFlipDetectorTest.filteredVsNaiveOnSameJitter`, `t12-ch2-jitter-counts.txt`)
  - บนเครื่อง ก่อนแก้: `t12-ch2-tilt-before.txt/.png` เอียง 25° แล้วนับเสียสมาธิ
  - บนเครื่อง หลังแก้: `t12-ch2-tilt-after.txt/.png` เอียง 25° ยังนับต่อ

### 5.3 หมุนจอถูกนับว่าออกจากแอป
- **ปัญหา:** ตอนหยิบมือถือขึ้นมาจอมักหมุน แล้วแอปนับเสียสมาธิ
- **สาเหตุ:** การหมุนจอทำให้ Activity ถูกสร้างใหม่ ผ่าน `onPause` เหมือนการสลับแอป
- **วิธีแก้:**
  - ใน `onPause` ตรวจ `isChangingConfigurations` ถ้าเป็นการหมุนจอจะไม่นับเป็นการออกจากแอป
  - สถานะส่งต่อผ่าน `onSaveInstanceState`
- **ปัญหาที่เจอระหว่างแก้:**
  - layout แนวตั้งกับแนวนอนใช้ id `content` ซ้ำกันกับ view ต่างชนิด (ScrollView กับ LinearLayout)
  - ทำให้ crash ตอนคืนสถานะ (`ClassCastException ... ScrollView$SavedState`) จึงเอา id นั้นออก
- **หลักฐาน:**
  - ก่อนแก้: `t12-ch3-rotation-before.txt` (ผลเทสต์ `expected:<0 times> but was:<1 times>`)
  - หลังแก้: `t12-ch3-rotation-after.txt` (ผ่าน)
  - เทสต์: `MainActivityRotationTest`

### 5.4 ปัญหาที่พบจากการตรวจโค้ดรอบสุดท้าย (แก้แล้ว พร้อมเทสต์)
- **ยกมือถือขึ้นดูระหว่างพัก แล้วคว่ำใหม่ รอบถัดไปไม่เริ่ม**
  - สาเหตุ: กฎ "หลังพักต้องหยิบแล้วคว่ำใหม่" ไม่ได้ดูว่าระหว่างพักมือถือถูกหยิบไปแล้ว
  - แก้ใน `FocusSession` ให้จำท่าล่าสุด
  - เทสต์: `liftedDuringBreakLetsNextFlipStartRound`
- **ช่วง ~1 วินาทีก่อนจอดำขึ้น จอที่คว่ำบนโต๊ะอาจแตะโดนปุ่ม "จบการอ่าน"**
  - แก้โดยกันการแตะทันทีที่ค่าแรงโน้มถ่วงบอกว่าจอคว่ำ (`screenDown`) และให้ปุ่มจบการอ่านถามยืนยันก่อน
  - เทสต์: `screenDownReportedBeforeHoldCompletes`, `MainActivityEndConfirmTest`; ภาพ `t12-end-confirm.png`
- **ข้อมูลที่บันทึกไว้อ่านได้แต่มีค่าผิด (เช่น พักยาวทุก 0 รอบ) ทำให้แอป crash ทุกครั้งที่เปิด**
  - แก้ให้ `SessionCodec.decode` ตรวจช่วงค่าทุกช่อง
  - เทสต์: `decodeRejectsParseableButInvalidValues`

## 6. ประเด็นที่คำนึงถึงในการพัฒนา

### 6.1 ขนาดและความละเอียดหน้าจอ

- `values/strings.xml` + `values-th/strings.xml` ครอบคลุมทุกข้อความ รวม toast และ dialog

- ภาพ: `t12-en-light-*.png` เทียบกับ `t12-th-light-*.png`, dialog ภาษาไทย `t12-back-02-exit-dialog.png`, `t12-delete-01-confirm.png`

### 6.3 Day theme และ Night theme

### 6.5 การหยุดและกลับมาทำงานต่อ
- สลับแอป, กด Home, ปุ่ม power, สายเรียกเข้าหรือการแจ้งเตือนที่พาไปแอปอื่น ทั้งหมดผ่าน `onPause` เหมือนกัน
- **รอบอ่าน:** เวลาหยุด และนับเสียสมาธิในโหมดตรวจจับ กลับมาแล้วคว่ำมือถือ (หรือกด "ทำต่อ") เพื่ออ่านต่อจากเวลาเดิม
- **ช่วงพัก:** เวลาพักหยุด แล้วนับต่อเมื่อกลับมา
- เสียงเตือนและเสียงตัวอย่างหยุดใน `onPause`
- ถ้าระบบปิดแอปขณะอยู่เบื้องหลัง เปิดใหม่แล้วยังเห็นการอ่านค้างในสถานะหยุดชั่วคราว (ตรวจด้วย `adb shell am force-stop` แล้วเปิดใหม่)
- ภาพ: `t12-flow-04-paused.png`
